3. github.com/Peterande/D-FINE, the training code, carries the Apache-2.0 text

     be assumed to be commercially cleared under the D-FINE license."
   This checkpoint is COCO only, with no Objects365 lineage, so the carve-out
   does not reach it. Objects365 states it is "available for the academic
   purpose only". Staying off those checkpoints is a standing rule, not a
   preference.

The claim here is deliberately narrow. It is not "the code is Apache-2.0, so the
weights are" — weights do not inherit a code licence, and OSI's Open Source AI
Definition treats parameters as separately licensable for exactly that reason.
It is that **the publisher of the weights declared them Apache-2.0**, and a
format conversion is a derivative work section 4 permits distributing, provided
this file travels with it. That is what this file is for, and it is why it is
copied into the container image beside the weights rather than kept in docs.

Why not onnx-community/dfine_n_coco-ONNX, which the research first measured:

- It declares no licence — no card metadata, no tag, no LICENSE file — so it
  states no terms and cannot discharge section 4 on anyone's behalf. Hugging
  Face documents no default for an untagged repository, and its own terms grant
  a platform licence rather than a redistribution one.
- Its export is dated 2025-04-30 and the base checkpoint was corrected on
  2025-08-20 in a commit titled "Fix weights", so it converts superseded
  weights. Measured on 32 on-track photographs, that costs 8 of 29 usable
  kart-and-driver boxes and roughly half the confidence.

What is not resolved, and is accepted rather than hidden:

- COCO's own terms license the annotations CC BY 4.0 and carry no
  non-commercial clause, but state that the Consortium does not own the images
  and that their use "must abide by the Flickr Terms of Use". Three of COCO's
  eight per-image Flickr licences are non-commercial. Whether that flows
  through to a trained model is unresolved and industry-wide; it is identical
  for every COCO-pretrained detector and so cannot distinguish between them.
  Written down here so it is a known risk rather than a discovered one.
- The Apache-2.0 file upstream has an unfilled copyright line —
  "Copyright [yyyy] [name of copyright owner]" — so it names no holder.

Unlike EdgeFace (LICENCE-edgeface.txt) nothing in this chain restricts
commercial use. This is a duty to discharge, not a risk to record, which is why
it needs no ADR.
